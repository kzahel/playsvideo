# Implementation Tactical Docs

Bounded implementation plans and execution records live here.

The first new tactical under this convention should be named
`000-{subject}.md`. Continue with the next unused zero-padded number, such as
`001-{subject}.md`, and add every tactical to the index below. Existing plans
elsewhere under `docs/` remain valid and do not participate in this numbering;
do not move or renumber them solely for consistency.

Keep one bounded implementation slice per tactical. A tactical should normally
record:

- its goal, scope, and important non-goals;
- relevant current behavior and constraints;
- ordered implementation slices with concrete completion checks;
- compatibility, rollout, and rollback concerns where applicable;
- validation evidence and final status as work lands.

Name steps for the product surface or work they cover. Completed tacticals are
historical execution records. Put continuing status, contracts, decisions, and
recommended next work in a focused [topic doc](../topics/README.md), then link
the tactical from that topic.
